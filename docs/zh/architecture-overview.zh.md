# MedCheck 架构导读（中文）

> 面向同学的通俗版导读，对应两份英文原始文档：`architecture-blueprint.md`（架构总纲 / 主约束文档）与 `docs/architecture/adr/001-deterministic-core-model-at-the-edges.md`（架构决策记录）。原名文档为准，本文不引入新约定。

---

## 1. 一句话

**模型只负责「看懂」，代码负责「决定」。**

系统读一段病历散文，输出一个结论（批准 / 挂起 / 拦截）。其中语言模型只做一件事：把散文变成结构化字段（药名、剂量原文、频次）。它看不到规则表、不输出结论、不算剂量。结论、严重程度、剂量数字全部由确定性代码产出，因此同一输入 + 同一张表版本 → 输出逐字节相同。

## 2. 为什么不让模型直接给结论

最省事的方案是一次模型调用问「这个处方安全吗」。它便宜、快，但有三个致命问题：

1. **不能离线证明。** 没有哪个测试的失败能证明「模型不该批准这个」，测试只能证明模型这次的心情。
2. **不可追溯。** 复核人问「为什么」，得到一段读起来很有道理的话，而不是一条规则编号加表版本。
3. **不能做回归。** 每次回归都要真调模型；用录制的假响应做测试，那是在测录像带。

而一次错误的「批准」比一次多余的「挂起」严重得多：挂起只花复核人一分钟。所以整个架构围绕一个不对称设计：**宁可多挂起，绝不静默放行。**

## 3. 权威接缝落地的三层

这是全项目最重要的一张表。任何一层单独失效，另外两层仍在。

| 层面 | 机制 | 证明它的测试 |
|---|---|---|
| 契约 | `ExtractionRecord` **没有**结论、严重程度、标准化剂量字段。模型想写也没地方写。 | `test_contract_has_no_authority_fields` |
| 代码 | 全仓库只有 `adjudicator/verdict.py` 能出现 `verdict = Verdict.APPROVE` | `test_single_approve_site` |
| 结构 | 感知层（`extractor/`）禁止 import 判决策（`adjudicator/`） | `test_no_authority_import` |
| 结果 | 没有显式通过发现、或覆盖不完整的 `APPROVE` 被拒绝 | `test_inv003_result_without_pass_finding_rejected` |

核心设计原则：**契约就是约束。** 检查载荷里有没有 verdict 字段的守卫只是第二道防线；第一道防线是这个类型根本没有那个字段。

## 4. 数据流

```
病历文本
  │
  ├─► privacy.mask ───────────── 脱敏（身份证/电话/姓名/生日 → 类型化令牌）
  │        │
  │        ├─► extractor（模型）── 只输出结构化字段，不含任何权威字段
  │        │        │
  │        │        ├─► rules.units ── 单位换算（封闭换算表，未知单位报错不猜）
  │        │        ├─► rules.ddi ──── 相互作用查表（含「声明空洞」）
  │        │        └─► rules.dose ─── 日剂量上限 + 肾功能分档
  │        │                 │
  │        └─► adjudicator ───┴─► 结论（APPROVE / HOLD / BLOCK）+ 有序发现
  │                                  │
  │                                  ├─► audit ──── 只追加、哈希链
  │                                  └─► renderer ─ 建议文案（终端汇点，下游不读）
  ▼
结果文档（JSON）
```

`renderer` 之所以被允许（将来）用模型，是因为**没有任何代码读它的输出**。它唯一的约束是一致性：每句话必须能落到某条发现或某个固定模板上。

## 5. 结论语义（规范）

按顺序评估，取最强结论：

| 顺序 | 条件 | 结论 | 发现码 |
|---|---|---|---|
| 1 | 任一药、或任一对药不在表覆盖内（含声明空洞） | `HOLD` | `COVERAGE_GAP` |
| 2 | 存在禁忌相互作用 | `BLOCK` | `DDI_CONTRAINDICATED` |
| 3 | 日剂量超过上限（按肾档调整后） | `BLOCK` | `DOSE_CEILING` |
| 4 | 存在重度相互作用；或该药需肾功能但病历没写 | `HOLD` | `DDI_MAJOR` / `RENAL_DATA_MISSING` |
| 5 | 仅轻/中度相互作用 | `HOLD` | `DDI_MINOR_MODERATE` |
| 6 | 覆盖完整且零发现 | `APPROVE` | `ALL_CHECKS_PASSED` |

`APPROVE` **只能**从第 6 条到达，且必须附一条显式的通过发现。代码里不存在「默认批准」的分支——任何不带覆盖证明就返回 `APPROVE` 的分支，按定义就是缺陷。

## 6. 五条不变量（零容忍）

| ID | 一句话 | 违反时的动作（具体动作，不是「修 bug」） |
|---|---|---|
| INV-001 | 覆盖不完整绝不能批准 | 判为 `HOLD` + `COVERAGE_GAP`，未覆盖项写入遥测；同名列一周内出现 ≥3 次则开表覆盖工单，并阻塞下一次表发布 |
| INV-002 | 上限只能是表推导值；超量必须有发现 | 抛 `CeilingAssertionError`，**不输出任何结果**（绝不发布部分结果），构建标记为不安全 |
| INV-003 | 模型不能写结论/严重程度/剂量 | 抛 `AuthorityViolation` 中止，载荷哈希以 ERROR 记录，P1 缺陷 + 一冲刺内补 ADR |
| INV-004 | 标识符不得未脱敏离开进程 | 发送前拦截（`MaskingError`），病例不调用模型；若日志泄漏则隔离并轮转日志，发布阻塞 |
| INV-005 | 发现必须能解析到规则与表版本 | 抛 `UnresolvableFinding`，不输出；表回滚到上一个已知良好版本 |

**改动政策：** 不变量只能因驱动因素变化而重新推导，不能「放宽」。数量可以增长，容忍度不行。

## 7. 六个驱动因素（冲突时序号小的赢）

1. **错误的批准不可接受** → 裁决必须确定性，未知即升级。
2. **输出里的数字不能来自模型** → 权威字段写保护。
3. **每个主张都要能追到规则** → 发现必须带 rule_id + 表版本。
4. **患者标识不得未脱敏外传** → 模型边界前脱敏。
5. **人要在几秒内复核完** → 建议 ≤200 词，按严重度排序，模板化。
6. **整条流水线要能离线跑 CI** → 确定性内核与夹具离线，只有 `test/live` 碰模型。

## 8. AI 组件的分层上下文（ADR §5）

每一轮给模型的六层，按优先级从高到低：

| 层 | 内容 | 典型 token | 可否压实 |
|---|---|---|---|
| L1 身份 | 「你是用药抽取器，不做安全判断」 | 320 | 否 |
| L2 常驻约束 | 「绝不输出结论/严重程度/剂量；不编造药名；解析不了就标 unparsed」 | 180 | **否，且压实后逐字重注入** |
| L3 检索知识 | 与病历匹配的药品词表、单位表 | 900 | 是（降到 40 条） |
| L4 会话历史 | 同一病例的纠错回合 | 600 | 是（留最近 2 轮） |
| L5 可恢复状态 | 上次已接受的抽取结果 + 未决问题 | 400 | 是（摘要化） |
| L6 当前任务 | 脱敏后的病历 + 本次指令 | 600 | 否（超限则拒收，绝不截断临床文本） |

**装配管线：** 去重 → 定优先级 → 预算（总上限 3000 token）→ 压实（阈值 2400，即 80%）→ 组装。
**重注入策略：** 任何一次压实之后，L2 在 L6 之前逐字重放，并在调用元数据里记录 `constraint_reinjected: true`。

为什么阈值定在 80%：撞上服务端截断会静默丢掉提示词尾部，而约束就放在尾部。

## 9. 权限模型（默认无读无写）

| 角色 | 能写 | 绝对不能写 |
|---|---|---|
| `plan-agent` | `docs/req/**`、`Report.md`、`transcripts/**` | 代码、测试、提示词、规则表 |
| `build-agent` | `src/**`、`test/**`、`scripts/**`、`prompts/**`、AI 日志、债务表、缺陷日记 | `AGENTS.md`、架构文档、`.opencode/**`、`.agent/**`、`.github/**`、`data/rules/**` |
| `verify-agent` | 只写 `docs/review-memo.md`、债务表、缺陷日记 | 其余全部 |

**人工专属（九个面）：** `AGENTS.md`、`architecture-blueprint.md`、`Prompt.md`、`docs/architecture/**`、`docs/code-governance/**`、`.opencode/**`、`.agent/**`、`.github/workflows/**`、`data/rules/**`。

理由一句话：**被约束方能修改的约束不是约束。**

## 10. 六个被否掉的方案与重开条件

| 方案 | 为什么否 | 什么时候重开 |
|---|---|---|
| 单次模型调用直接给结论 | 不变量无法离线证明 | 永不（除非产品不再是安全相关） |
| 模型评审团（三次调用互相评审） | 成本 3 倍破预算；相关错误让「一致」不等于「正确」 | 价格降 10 倍 + 需求变成「给置信分数」 |
| RAG 直接决策 | 检索漏召是静默假阴性 —— 最坏的失效 | 需求要求开放世界药名覆盖时，用它**提议表行**给人签，不在运行时决策 |
| 历史病例向量库 | 制造第二份未审计的 PHI 副本 | 有正式去标识管线与保留政策时 |
| 微调分类器给结论 | 没有标注语料；仍是概率性的 | 有 ≥5k 标注病例 + 需要校准风险分 |
| 让智能体自己写 ADR | 能写自己约束的人没有约束 | 永不 |

完整的十二个选项在 `docs/architecture/option-ledger.md`，每个都带「重开触发条件」。

## 11. 如果你想动手改

1. 先读 `AGENTS.md`（阅读顺序），再读架构总纲，再读 ADR。
2. 跑 `python -m pytest test/offline -q`，确认基线是绿的。
3. 任何改动前先问：**它会不会让某条不变量变得不可证明？** 会的话，先去写 ADR。
4. 改安全关键路径（`adjudicator`、`rules`、`privacy`、`audit`）需要：ADR 编号写进 PR、人工审查、不变量全绿。
5. 不要改 `data/rules/**`——那是人工专属；提一个 diff 让人来合。
