## 第 2 步 · 剪映里生成语音与字幕（约 25 分钟）

画面先录好，声音后配。这套流程的好处是：录屏时不用管口误，重录成本低。

### 2.1 先摆画面

导入 `seg1` … `seg7`，按时间码摆在主轨：

`0:00 / 0:40 / 2:30 / 4:10 / 5:50 / 7:20 / 8:50`

每段先裁掉开头的静置（留 0.3 秒即可）和结尾多余的等待（保留 1 秒）。

### 2.2 生成语音（文本朗读）

1. `文本` → `新建文本` → 粘贴 `vo-en.txt` 里 `SEG1` 之后的那一段（**不要带 SEG1 标记**）
2. 选中该文本 → `朗读` → 选音色
3. 生成后得到一条独立音频轨，把它拖到对应画面位置
4. 语速先保持 1.0，试听；画面偏短就调 0.95，画面偏长就调 1.05
5. 对 `SEG2` … `SEG7` 重复

**音色选择标准**（比名字更重要）：

- 能自然读出缩写：`ADR`、`API`、`eGFR`（英文音色一般没问题）
- 语气平稳、不夸张——这是一段技术说明，不是广告
- 男女皆可，**全片必须同一个音色**

> `vo-en.txt` 里的写法是为 TTS 准备的：`D D I zero zero seven`、`A D R`、`A P I`、`one hundred twenty five`。这样不会被读成「DDI 减七」或跳过数字。字幕用的是正常写法，两者分离，互不影响。

### 2.3 生成字幕

两条路，建议先试第一条：

| 方式 | 操作 | 适合 |
|---|---|---|
| **识别字幕** | 选中 TTS 生成的音频轨 → `识别字幕` → 批量校对 | 语音由 TTS 生成时最准，时间轴自动对齐 |
| **导入 SRT** | `文本` → `导入字幕` → 选 `subs-en.srt` | TTS 读得快/慢导致漂移时，手动调更省事 |

校对时重点看这几个词（自动识别常错）：

`HOLD` / `APPROVE` / `BLOCK` / `eGFR` / `DDI-007` / `ADR` / `DEBT-09`

### 2.4 中文版

如果要做中文口播或双语字幕，用 `vo-zh.txt` + `subs-zh.srt`，步骤完全相同。
中文 TTS 建议把语速降到 0.95，中文默认语速偏快，`挂起` 和 `拦截` 容易糊在一起。

## 第 2b 步 · 静音录制的三个额外要求

既然录的时候不说话，画面必须自己说得清：

1. **每段结尾多录 5 秒静止**。TTS 的时长不可预测，画面必须比声音长——长了可以裁，短了只能补录。
2. **动作放慢一半**。没有旁白解释时，观众靠看：命令敲完停 4 秒、文件打开后鼠标指着关键行停 15 秒。
3. **关键结论先上屏**。`HOLD` 那一屏建议在剪映里加一个大字标题（`HOLD ≠ ERROR`），否则纯 JSON 输出看不出重点。

另外，用 `cards.html` 的 `B` 键黑屏当**场记板**：每段开录前黑屏 1 秒、停止前再黑屏 1 秒，剪辑时一眼就能找到切点，不需要靠听声音对齐。

## 出问题时

| 现象 | 原因 | 处理 |
|---|---|---|
| `ModuleNotFoundError: medcheck` | `PYTHONPATH` 不是 Windows 路径 | 重新执行 `export PYTHONPATH="$(cygpath -w "$PWD/src")"` |
| 录出来只有一半屏幕 | `Win+G` 录的是「当前窗口」 | 先点一下目标窗口再开始录 |
| 命令里出现中文标点 | 输入法没关 | `Shift` 切英文；或直接右键粘贴 |
| 录到的画面发虚 | 显示缩放不是 100% | 设置 → 显示 → 缩放 100% |
| 配音和画面对不上 | 先剪画面再配音 | 顺序反了，按「画面 → 配音 → 字幕」重来 |
