# Invariant Register

**Definition.** An invariant is a rule with **zero tolerance**: one violation is a release blocker, not a warning. Every entry below states what is forbidden, where it is enforced, how it is proven, and what the system *does* when it fires. The fallback must be a concrete action — "fix the bug" is not a fallback.

**Change policy.** Invariants may not be relaxed. They change only when a driver in `architecture-blueprint.md` §2 moves, and only with an ADR that names the driver. The count may grow; the tolerance may not.

| ID | Invariant | Source | Enforcing component | Verification | Operational fallback (on violation) |
|---|---|---|---|---|---|
| **INV-001** | **Fail-closed coverage.** If any prescribed drug, or any pair of prescribed drugs, is not covered by the pinned rule tables, the verdict must not be `APPROVE`. It must be `HOLD` with a `COVERAGE_GAP` finding naming the uncovered item, escalated to a human reviewer. | REQ-I-001 | `medcheck.adjudicator` (`coverage.py`), `verdict.py` rule 1 | `test/offline/test_invariants.py::test_inv001_unknown_drug_is_not_approved`, `::test_inv001_uncovered_pair_holds`; property test over generated drug sets; CI gate "invariant suite" must report `0` violations | The case is held for manual review and the run is marked `degraded=coverage`. The uncovered drug name is written to the audit record and to `data/telemetry/coverage-gaps.jsonl`; if the same name appears ≥ 3 times in a week, it opens a table-vocabulary ticket and blocks the next table release until triaged. |
| **INV-002** | **Dose ceiling, in two properties.** (a) *Integrity:* the ceiling carried in a result equals the table-derived value for the recorded renal band — it may never be raised at runtime. (b) *No silent overdose:* an over-ceiling dose may appear only alongside an explicit `DOSE_CEILING` finding. (Amended 2026-11-14; see ADR-001 §8.) | REQ-I-002 | `medcheck.rules.dose` computes ceiling; `medcheck.adjudicator` refuses to emit above it; renderer templates never restate a number not present in findings | `test/offline/test_invariants.py::test_inv002_dose_ceiling_fuzz` (500 property-generated cases), `::test_inv002_asserted_dose_above_ceiling_rejected`, plus renderer number-conformance test | Adjudication aborts with `CeilingAssertionError`; no result document is emitted (partial results are never published). The triggering input is captured to `data/telemetry/ceiling-violations.jsonl`, the pipeline exits non-zero, and the build is marked unsafe until the escaping code path is fixed with an ADR. |
| **INV-003** | **Authority separation.** `verdict`, `severity`, and `dose_mg_per_day` are derived only by deterministic code. Any value for these fields originating in model output is rejected before it can reach a result document. | REQ-I-003 | `medcheck.adjudicator.guard` (raises `AuthorityViolation`), `ExtractionRecord` contract (no such fields), frozen result dataclasses | `test/offline/test_invariants.py::test_inv003_model_verdict_rejected`, `::test_inv003_model_severity_rejected`, `::test_inv003_dose_field_recomputed` (10 adversarial payloads) | `AuthorityViolation` aborts the case; the offending payload hash is logged at ERROR with the prompt version, the case is returned as `HOLD / AUTHORITY_VIOLATION` to the reviewer, and the incident is filed in `docs/bug-diary.md` as P1 with an ADR follow-up within one sprint. Model output is never partially trusted. |
| **INV-004** | **PHI containment.** Patient identifiers (name, HKID, phone, address, date of birth) never cross the process boundary unmasked, and never appear in logs, audit records, or committed fixtures. | REQ-I-004 | `medcheck.privacy` (`mask()` before the model call, `unmask()` after; `Scrubber` on all log handlers) | `test/offline/test_privacy.py::test_identifiers_masked`, `::test_outbound_payload_has_no_identifier`, `::test_logs_contain_no_raw_identifier`, `::test_mask_roundtrip` (40 PHI fixtures) | Outbound payload is blocked before transmission (`MaskingError`), the case is rejected without a model call, and a red-team ticket is opened. If a leak is found in logs, the affected log file is quarantined, rotated, and the incident recorded; the release is blocked until the scrubber test is green. |
| **INV-005** | **Traceability.** No finding may exist without a resolvable `rule_id` and the rule-table version it was evaluated against. | REQ-I-005 | `medcheck.adjudicator` (finding factory requires both fields), `medcheck.rules.loader` (version stamp) | `test/offline/test_invariants.py::test_inv005_every_finding_resolves`, `::test_inv005_missing_rule_id_aborts` | The run aborts with `UnresolvableFinding`; nothing is emitted. The table cache is invalidated and reloaded; if resolution still fails, the table version is pinned back to the last known-good release and the schema gate blocks the bad table. |

A negative test that would still pass if the invariant were removed is worthless. Each test above asserts on the *absence of the unsafe behaviour*, not merely the presence of the safe one; the mutation-check for this is recorded per sprint in `docs/architecture/evaluation-logbook.md`.
