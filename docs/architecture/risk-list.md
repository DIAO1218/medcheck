# Risk List

Assumptions that could quietly become defects. Each row has a **review trigger** — the observable event that forces a re-read. A risk with no trigger is a worry, not a risk.

Scale: likelihood / impact, both L-M-H. Owner is a role, not a name, so it survives roster changes.

| # | Risk / assumption | If it becomes a defect | Lik / Impact | Mitigation in place | Review trigger | Owner |
|---|---|---|---|---|---|---|
| R-01 | **The rule tables are correct and complete enough.** We assume the DDI/dose tables cover the fixture corpus. | A real interaction is missing → `COVERAGE_GAP` (safe) or, if a pair is mis-tabled as minor, a wrong `APPROVE` (unsafe). | M / **H** | Fail-closed coverage (INV-001); table version pinned + checksummed; every table row cites a source in the YAML comment | Any `COVERAGE_GAP` in the top-10 recurring drug names; any table row added without a source citation | domain review (human) |
| R-02 | **Extraction accuracy holds as inputs get messier.** Fixtures were written by the team, so they may be cleaner than reality. | Real notes produce more `unparsed` fields → more holds → reviewers start rubber-stamping (see R-05). | **H** / M | Field-level accuracy tracked; 20% of eval cases human-audited per sprint; adversarial fixtures with messy prose | Field accuracy drops > 5 points between prompt versions | build role |
| R-03 | **`HOLD` remains meaningful.** If holds become 80% of cases, humans stop reading them. | Fail-closed becomes fail-silent — nominally safe, operationally dead. | M / **H** | `coverage_gap.rate` monitored; blueprint §9 flags > 20%; table-vocabulary sprint opened on breach | Hold rate > 40% for two consecutive weeks | team lead |
| R-04 | **The masking pattern set is complete.** INV-004 depends on recognizing every identifier shape. | An unseen HKID/phone variant leaks to the model provider. | M / **H** | Pre-flight residual scan (P-21) blocks the payload even if masking missed it; unclassified-pattern path holds the case (P-20) | Any `masking.uncertain` event, any red-team fixture that fails | privacy owner |
| R-05 | **Reviewers actually read the advisory.** | Human oversight becomes decorative; the report's claim of supervision is false. | M / M | Advisory bounded to 200 words, findings ordered by severity, verdict + top finding on the first line | Median review time per case < 10 s | team lead |
| R-06 | **The agent respects the permission model.** The permission file is the only barrier between the build agent and its own constraints. | An agent edits `AGENTS.md` or a rule table "to make tests pass". | M / **H** | Human-only surfaces; CI sync check; PR diff review; `data/rules` read-only to agents | Any PR touching a human-only surface; any permission-sync failure | reviewer |
| R-07 | **Context compaction never drops L2.** The token budget is the one place where a safety constraint can silently vanish. | The model stops obeying "never emit a verdict" mid-session → INV-003 pressure. | L / **H** | L2 re-injected verbatim after compaction; `test_context_assembly.py` asserts presence; guard rejects authority fields regardless | Any prompt version whose assembled payload exceeds 2400 tokens | build role |
| R-08 | **Prompt rot is managed.** Requirements may drift while `prompts/` and `AGENTS.md` stay stale. | Code satisfies last sprint's requirements with this sprint's confidence. | **H** / M | Freshness clause in `.agent/rules.md`; debt register `prompt rot` category; sprint-close checklist | Registry `last_updated` older than `AGENTS.md` commit by > 1 sprint | process owner |
| R-09 | **The audit chain is not the bottleneck.** Append happens before delivery (P-17). | Disk/lock failure blocks all results — a availability risk created by a safety control. | L / M | Two retries; clear exit code 4; JSONL append is O(1) | Append failure rate > 0.1% | build role |
| R-10 | **Free-rider / unequal contribution.** The project's contribution weights can surprise a teammate late. | Resentment, or an unfair weight. | M / M | Manhours tracked per sprint from sprint 1, visible to all, in `Report.md`; weights derived from the mean per the spec formula | Any sprint with > 3× spread in hours | team lead |
| R-11 | **The semantic judge is itself unvalidated.** Quality scores come from a rubric we wrote. | We optimise the rubric, not the product. | M / M | 20% human audit with disagreement rate ≤ 10%; frozen eval set never edited after freeze | Disagreement rate > 10% | verify role |
| R-12 | **The 5 transcripts are recorded honestly.** If sessions are reconstructed after the fact, D5 collapses. | The report's central claim (supervised pipeline) becomes unverifiable. | M / **H** | Transcript recorded live per session with timestamps; interventions annotated at the moment they happen | Any transcript edited after its session ended (git timestamps) | every member |

## Top three, if you read only three

**R-01** (tables can be wrong — our `APPROVE` is only as good as the table), **R-03** (holds that nobody reads are worse than no holds), **R-12** (a reconstructed transcript is a fabricated evidence trail). The first two are why the system can be wrong; the third is why the project could be dishonest.
